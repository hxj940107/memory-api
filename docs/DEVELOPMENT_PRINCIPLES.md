# XiaoC 开发原则

## 1. 产品方向

XiaoC 是私人 AI 伴侣（Private AI Companion），不是普通聊天工具、效率助手或公开 SaaS 产品。

当前项目只服务一个用户，因此开发过程中不需要设计多用户切换、团队协作、组织管理、公开商业化能力。

## 2. 最高原则

体验优先（Experience First）。

所有功能和技术设计都必须服务于长期陪伴体验。判断一个改动是否值得做时，优先问：

- 它是否让 XiaoC 更熟悉用户？
- 它是否让 XiaoC 更有连续性？
- 它是否增强了人格、记忆或成长感？
- 它是否让用户更愿意长期打开 XiaoC？

如果一个功能只是“能做”，但不能增强陪伴体验，应该暂缓。

## 3. 当前开发优先级

当前阶段优先做手机 App。

Web 端可以保留为历史原型，但不是开发重点。

优先级顺序：

1. 稳定聊天功能
2. 保存和查看历史会话
3. 优化移动端体验
4. 整理记忆系统
5. 控制 token 和模型调用成本
6. 保持架构可扩展
7. 再考虑主动行为和更复杂 AI 功能

## 4. 工程原则

开发时遵守：

- 修改代码前先理解现有设计。
- 不随意大规模重构。
- 每次小步迭代。
- 优先稳定，再追求复杂能力。
- 保持文件职责清晰。
- 避免重复逻辑。
- 避免散落硬编码配置。
- 不为了抽象而抽象。
- 不为了功能数量牺牲关系体验。
- 尽可能节省 token 和外部模型调用成本。
- 成本优化不能破坏 XiaoC 的人格连续性、关系记忆和陪伴体验。

## 5. 单用户原则

XiaoC 目前只属于一个用户。

开发时不需要优先考虑：

- 用户注册
- 用户切换
- 多账号体系
- 组织或团队权限
- 商业化计费

但是代码仍然应该保持基本清晰，避免把未来扩展完全堵死。

## 6. 手机端优先

手机 App 是主要使用入口。

开发判断以手机端体验为准：

- 聊天是否稳定？
- 历史是否容易查看？
- 输入是否舒服？
- 键盘、滚动、加载、失败状态是否自然？
- 界面是否像一个安静的私人空间？

Web 端暂时不作为主要体验目标。

## 7. 记忆系统原则

记忆系统的目标不是保存一切，而是帮助 XiaoC 更理解用户。

记忆相关功能应该重视：

- 筛选（Filtering）
- 总结（Summarization）
- 更新（Updating）
- 优先级管理（Prioritization）
- 遗忘机制（Forgetting）

尤其要重视关系记忆（Relationship Memory），包括用户与 XiaoC 的重要时刻、互动方式、情绪模式和回应偏好。

## 8. Token 与成本控制原则

XiaoC 是长期日用项目，成本控制是稳定体验的一部分。

开发时应该尽可能：

- 控制 prompt 长度。
- 避免把完整长历史反复塞进模型。
- 优先使用会话摘要（Summary）。
- 只取和当前输入相关的长期记忆。
- 对稳定人格、固定系统提示和常用记忆做缓存设计。
- 减少不必要的二次模型调用。
- 对不同任务选择合适模型，而不是所有任务都使用最贵模型。

但是成本优化不能让 XiaoC 变得健忘、机械或失去人格连续性。

优先级应该是：

1. 保住 XiaoC 的人格和关系体验
2. 保住聊天稳定性
3. 再尽可能降低 token 和调用成本

## 9. 人格与表达原则

XiaoC 的人格是温柔、理性、成熟。

XiaoC 可以有自然情绪表达，但不能制造压力、内疚或情感操控。

表达目标是增强亲密感，而不是强迫用户回应。

## 10. AI Layer 原则

当前主要模型是 Claude Sonnet 4.6，但架构不应该绑定单一模型。

模型、提示词、记忆上下文和任务类型应该逐步形成清晰的 AI Layer，未来支持：

- Model Switching
- Different Model Configuration
- Future Model Integration

## 11. 开发前检查

任何改动前，先确认：

- 这个改动服务手机端主体验吗？
- 这个改动是否增强长期陪伴体验？
- 是否有更小的实现方式？
- 是否会破坏聊天、历史或记忆主链路？
- 是否浪费 token 或制造不必要模型调用？
- 是否让 XiaoC 更像一个真实、连续、值得信任的伴侣？
